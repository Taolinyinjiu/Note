# Overview 综述

## Introduction 介绍

**MuJoCo**全称为**Mu**lti-**Jo**int dynamics with **Co**ntact(多关节动力学与接触)。它是一个通用的物理引擎，旨在促进机器人学，生物力学，图形与动画，机器学习领域的研究与开发。这些领域通常需要对与环境进行交互的关节结构进行快速且准确的模拟。
MuJoCo 最初由 Roboti LLC 开发，随后在 2021 年 10 月被 DeepMind 收购并免费开放，并于 2022 年 5 月正式开源。目前，MuJoCo 的代码托管在 GitHub 的 google-deepmind/mujoco 仓库中。

## Key Features 关键功能

MuJoCo 拥有丰富的功能列表。这里我们概述了最著名的几项。

- 广义坐标系与现代接触动力学的结合
  - 物理引擎传统上分为两大类。机器人学和生物力学引擎在广义坐标（generalized coordinates）或关节坐标下使用高效且精确的递归算法。然而，它们要么忽略了接触动力学，要么依赖于早期的弹簧-阻尼方法（spring-damper approach），而这种方法需要极小的时间步长。游戏引擎则采用了一种更现代的方法，通过解决优化问题来计算接触力。但是，它们通常求助于过指定的笛卡尔表示法（Cartesian representation），其中关节约束是通过数值方式施加的。当涉及复杂的运动学结构时，这会导致不准确和不稳定的问题。MuJoCo 是第一款结合了两者优点的通用引擎：它既支持广义坐标下的仿真，又支持基于优化的接触动力学。 虽然近期其他仿真器也开始尝试采用 MuJoCo 的方法，但由于它们在设计之初并非以此为核心，这种适配通常无法与其所有功能兼容。习惯于游戏引擎的用户最初可能会觉得广义坐标不符合直觉；详情请参阅下文的“澄清（Clarifications）”部分。
- 软接触、凸接触和解析可逆接触动力学
  - 在现代接触动力学方法中，由摩擦接触产生的力或冲量通常被定义为线性或非线性互补问题（LCP 或 NCP）的解，而这两类问题都属于 NP-hard（非定式多项式困难）问题。MuJoCo 基于一种不同的接触物理公式，该公式将其简化为一个凸优化问题（Convex Optimization），具体细节在“计算（Computation）”章节中有详细阐述。我们的模型允许软接触（Soft Contacts）和其他约束，并具有唯一定义的逆动力学（Inverse Dynamics），这极大地方便了数据分析和控制应用。在算法选择上，MuJoCo 提供了多种优化算法，包括一种可以处理椭圆摩擦锥（Elliptic Friction Cones）的广义投影高斯-赛德尔方法（Projected Gauss-Seidel）。该求解器能够统一处理各类约束，包括： 
    - 带摩擦的接触（涵盖扭转摩擦和滚动摩擦）
    - 无摩擦接触
    - 关节和腱（Tendon）的限位
    - 关节和腱的干摩擦
    - 以及各种等式约束（Equality Constraints）以及各种等式约束（Equality Constraints）
- 肌腱几何结构
  - MuJoCo 能够模拟 腱（Tendons） 的 3D 几何结构——这些腱被定义为遵循绕桩约束（Wrapping Constraints）和经过点约束（Via-point Constraints）的最小路径长度弦线。该机制与 OpenSim 软件中的机制类似，但为了提高计算速度，MuJoCo 实现了一套更受限的、闭式解（Closed-form）的绕桩选项。此外，它还提供了针对机器人设计的特定结构，例如滑轮（Pulleys）和耦合自由度（Coupled Degrees of Freedom）。腱不仅可以用于驱动（Actuation），还可以用于对腱的长度施加不等式或等式约束。
- 一般驱动模型
  - 在采用模型无关（Model-agnostic）的 API 的同时，设计一个功能足够丰富的驱动模型极具挑战性。MuJoCo 通过采用一种抽象驱动模型实现了这一目标，该模型可以包含不同类型的：
    - 传动机构 (Transmission)
    - 力生成机制 (Force Generation)
    - 内部动力学 (Internal Dynamics)（即可以让整体动力学变为三阶的状态变量）。
  - 通过对这些组件进行实例化，MuJoCo 能够以统一的方式模拟电机（Motors）、气动和液压缸、PD 控制器、生物肌肉以及许多其他执行器。
  

## Model instances 模型实例

在 MuJoCo 中，被称为“模型”的实体有多个。用户首先在以 MJCF 或 URDF 格式编写的 XML 文件中定义模型。随后，软件可以在不同的介质（文件或内存）以及不同的描述层级（高级或低级）上，为同一个模型创建多个实例。

所有的运行时计算都是通过 mjModel 完成的，但它的结构过于复杂，不适合手动创建。这就是为什么我们设计了两个层级的建模。高级层级（High level）的存在是为了方便用户使用：它的唯一目的就是被编译成低级模型（Low level model），从而进行物理计算。

生成的 mjModel 可以加载或保存为二进制文件（MJB），但这些文件受版本限制且无法反编译。因此，用户应始终以 XML 文件的形式来维护模型。

C 语言结构体 mjSpec 与 MJCF 文件格式是一一对应的。XML 加载器会解析 MJCF 或 URDF 文件，创建相应的 mjSpec，并将其编译为 mjModel。用户也可以通过编程方式创建 mjSpec，然后将其保存为 MJCF 或直接进行编译。有关程序化创建和编辑模型的方法，在“模型编辑（Model Editing）”章节中有详细说明。

## Model elements 模型元素

本节将简要描述 MuJoCo 模型中可以包含的所有元素。稍后，我们将详细解释其底层的计算方式、在 MJCF 文件中的定义规范，以及它们在 mjModel 结构体中的呈现形式。

### Options 选项

每个模型都包含以下三组选项。无论用户是否在 XML 文件中明确指定，它们都始终存在（未指定时将使用默认值）。这些选项的设计允许用户在每个仿真时间步（time step）开始前修改其数值；但在一个时间步的计算过程中，不应更改任何选项。

- mjOption (物理选项) 该结构体包含了所有影响物理仿真的选项。它用于选择特定的物理算法并设置其参数、开启或禁用仿真流程中的不同部分，以及调整重力等系统级物理属性。
- mjVisual (视觉选项) 该结构体包含了所有的可视化选项。虽然 MuJoCo 还有其他的 OpenGL 渲染选项，但那些选项取决于当前的运行会话（session-dependent），不属于模型本身的一部分。
- mjStatistic (模型统计信息) 该结构体包含了由编译器计算出的模型统计数据，例如：物体的平均质量、模型的空间范围等。包含这些信息是为了便于查阅，同时也因为可视化器（visualizer）需要利用这些数据进行自动缩放（automatic scaling）。

### Assets 资源

**资源（Assets）**本身并不是模型元素。模型元素可以引用资源，在这种情况下，资源会以某种方式改变引用元素的属性。一个资源可以被多个模型元素引用。由于包含资源的唯一目的是为了引用它，且引用只能通过名称进行，因此每个资源都有一个名称。相比之下，普通元素的名称可以留空。

### Mesh 网格

MuJoCo 可以从 OBJ 和二进制 STL 文件中加载三角网格。您可以使用 MeshLab 等软件转换其他格式。虽然任何三角形集合都可以作为网格加载和显示，但碰撞检测器使用的是其凸包（Convex Hull）。

- 功能：支持缩放、拟合基本几何形状，以及通过将网格视为三角锥集合来自动推算惯性属性。
- 渲染：网格本身没有颜色，其颜色由引用它的几何体（Geom）的材质属性决定。
- 格式：支持 OBJ 和用于法线/纹理坐标的自定义二进制格式，也可以直接嵌入 XML 中。

### Skin 蒙皮

蒙皮网格是在运行时可以变形的网格。它们的顶点关联到刚体（在此背景下称为“骨骼”），每个顶点可以属于多个骨骼，从而实现平滑的变形。

- 性质：蒙皮纯粹是视觉对象，不影响物理计算，但能显著增强视觉真实感。
- 应用：在自动生成复合柔性对象时，编译器也会为这些对象生成蒙皮。

### Height field 高度场

高度场可以从 PNG 文件（内部转换为灰度图）或自定义二进制格式加载。它是一个高程数据的矩形网格。

- 处理：编译器将数据归一化到 [0-1] 范围，实际空间范围由引用它的几何体的尺寸参数决定。
- 限制：高度场只能由连接到“世界体”（world body）的几何体引用。
- 碰撞：网格矩形会自动三角化。如果单个几何体对产生超过 64 个接触点，则只保留前 64 个。因此，高度场应主要用于建模地貌，其特征尺寸应大于仿真中的其他物体。

### Texture 纹理

纹理可以从 PNG 文件加载，也可以由编译器根据程序化参数合成。

- 动态性：可以在创建模型时留空并在运行时更改，从而在仿真中渲染视频或创建其他动态效果。
- 映射方式：支持 2D 映射（适用于平面和高度场）和 立方体映射 (Cube mapping)（适用于 3D 物体“收缩包裹”纹理或创建天空盒）。
- 引用层级：纹理不能被模型元素直接引用，必须先由**材质（Material）**引用，再由材质被模型元素引用。

### Material

材质用于控制几何体（Geom）、站点（Site）和腱（Tendon）的外观。

- 外观属性：包括纹理映射以及与 OpenGL 光照交互的属性：RGBA、镜面反射、光泽度、发射光。
- 反射：可使物体具有反射性（目前仅支持平面和盒子的 Z+ 面）。
- 优先级：如果同时指定了材质和本地 RGBA 参数，本地定义具有更高优先级。
